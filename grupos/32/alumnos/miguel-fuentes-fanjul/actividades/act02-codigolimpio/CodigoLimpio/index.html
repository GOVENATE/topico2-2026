Introducción

Esta página resume los conceptos más importantes del libro "Código Limpio".

📌 Idea Central

El código limpio no es un lujo. Es la forma de mantener la productividad y facilitar la evolución de un proyecto.

"La única manera de avanzar rápido es mantener el código limpio."

🏕 Regla del Boy Scout

Cada vez que modifiques código debes dejarlo mejor de como lo encontraste.

  • Mejorar nombres.
  • Eliminar duplicaciones.
  • Dividir funciones largas.
  • Reducir complejidad innecesaria.

🏷 Importancia de los Nombres

  • Los nombres deben revelar la intención.
  • Deben poder pronunciarse fácilmente.
  • Deben ser fáciles de buscar.
  • Deben evitar ambigüedades.
Un buen nombre puede eliminar la necesidad de un comentario.

⚙ Funciones Pequeñas

Las funciones deben hacer una sola cosa y hacerla bien.

  • Cortas y simples.
  • Pocos parámetros.
  • Responsabilidad única.
  • Fáciles de leer y probar.

♻ Evitar la Duplicación

La duplicación genera más trabajo y más errores.

  • Mayor mantenimiento.
  • Cambios inconsistentes.
  • Más posibilidades de fallos.

💬 Comentarios

Los comentarios no sustituyen un código bien escrito.

  • Pueden quedar obsoletos.
  • Pueden mentir si el código cambia.
  • Es mejor mejorar el código que explicarlo demasiado.

✅ Pruebas

Las pruebas permiten modificar el sistema sin miedo.

  • Deben ser legibles.
  • Deben mantenerse limpias.
  • Son parte fundamental del proyecto.

🎯 Conclusión

La calidad del software no proviene de una única gran decisión, sino de miles de pequeñas decisiones correctas.

"Deja siempre el código un poco mejor de como lo encontraste."
