01 — Contexto

¿De qué trata el libro?

Martin plantea que la calidad del software no depende únicamente de que funcione: también importa qué tan fácil resulta comprenderlo y cambiarlo.

EL AUTOR

Robert C. Martin

Conocido como “Uncle Bob”, es un ingeniero de software y autor que promueve principios de diseño, desarrollo ágil y buenas prácticas de programación.

LA PROPUESTA

Calidad que se puede mantener

El libro reúne criterios y ejemplos para reconocer código confuso, reducir complejidad y construir programas más legibles y resistentes al cambio.

“La diferencia entre un programador profesional y uno aficionado está en el cuidado que pone en su trabajo.”IDEA CENTRAL DEL LIBRO
02 — Ideas fundamentales

Seis hábitos de código limpio

Selecciona cada idea como una lista de comprobación mental al diseñar, escribir o revisar un programa.

Aa

Nombres significativos

Usa nombres que revelen intención. Evita abreviaturas misteriosas y datos cuyo propósito no se entiende.

ƒ

Funciones pequeñas

Cada función debe concentrarse en una tarea. Su nombre y su contenido deben expresar el mismo propósito.

//

Comentarios útiles

Prefiere código que se explique por sí mismo. Comenta el contexto o las decisiones que no son evidentes.

▤

Formato consistente

La organización visual ayuda a encontrar relaciones, leer de arriba abajo y reconocer la estructura del programa.

✓

Pruebas confiables

Las pruebas deben ser claras, rápidas, independientes y repetibles. También necesitan diseño y mantenimiento.

↻

Mejora continua

Refactoriza en pasos pequeños. El código debe evolucionar sin acumular duplicaciones ni complejidad innecesaria.

03 — Taller de lectura

Del código confuso al claro

Compara dos formas de resolver una misma tarea. La segunda versión comunica mejor la intención.

Ejemplo interactivo

Un nombre también es documentación.

Imagina que encuentras una variable llamada x. Para comprenderla necesitas buscar dónde se declara y qué representa.

Un nombre descriptivo reduce esa carga mental y hace que el código sea más fácil de revisar.

RECUERDA
Elige nombres pronunciables, buscables y específicos del dominio.
COMPARADOR DE CÓDIGOJAVA · EJEMPLO
✕ Antes · poco expresivo
int d;
d = 5;
double p = 100;
double r = p * d;
✓ Después · intención clara
int rentalDays = 5;
double dailyPrice = 100;
double totalCost =
  dailyPrice * rentalDays;
La lógica no cambió: mejoró la lectura.
04 — Lista de revisión

Antes de entregar tu código

Una revisión rápida para detectar oportunidades de mejora. Marca los puntos que ya aplicaste.

01
¿Los nombres explican su propósito?
Variables, métodos y clases son fáciles de identificar.
02
¿Cada función hace una sola cosa?
Evita mezclar responsabilidades distintas.
03
¿Eliminé duplicaciones?
Una regla de negocio no debería repetirse sin necesidad.
04
¿Las pruebas verifican el comportamiento?
Comprueba casos normales y situaciones límite.
05
¿Dejé el código mejor de como lo encontré?
Aplica la regla del Boy Scout en cambios pequeños.
